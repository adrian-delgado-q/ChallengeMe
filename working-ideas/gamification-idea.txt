This gamification system is a **Hybrid Progression Model** designed to keep users engaged for both the short and long term. Think of it like a character in a role-playing game: you have an overall character level, but you also have individual skills you can master.

Here's a breakdown of the core components:

---

### 📈 Pillar 1: The Main Journey (Overall XP & Levels)

This is the primary, easy-to-understand progression path for every user.

* **What it is**: A single account level (Level 1-100, for example) that represents a user's total engagement across the entire app.
* **How it works**: Users earn **Experience Points (XP)** for nearly everything they do: logging an activity, completing a workout, joining a challenge, or even commenting on a post.
* **Key Feature**: The system tracks both **current XP** (for the next level up) and **total points** (a lifetime score). This means you can have exciting level-ups while still maintaining a fair, all-time leaderboard based on the total score.

---

### 🏋️ Pillar 2: Activity Mastery (The Specialist's Path)

This is the system's engine for long-term, deep engagement. It rewards dedication to specific activities.

* **What it is**: A separate leveling system for *each individual activity type*. A user can be a "Grandmaster Runner" while also being a "Novice Yogi."
* **How it works**: When you log a 5km run, your "Running Mastery" goes up. When you complete a weightlifting session, your "Weightlifting Mastery" increases. Progress is measured by the total accumulated value (e.g., total kilometers run, total reps lifted).
* **Why it's powerful**: It creates endless goals. Users can choose to master one discipline or become a jack-of-all-trades by leveling up many different activities. It's also incredibly scalable—add a new activity type to your app, and it automatically gets its own mastery path.

---

### 🏆 Pillar 3: Badges & Achievements (The Trophy Case)

These are one-time rewards for accomplishing specific, noteworthy goals.

* **What it is**: Collectible digital trophies that appear on a user's profile.
* **How it works**: Badges are unlocked by hitting specific milestones that the other systems don't cover. Examples include:
    * **Feats**: "Run a full marathon in a single session."
    * **Consistency**: "Log an activity for 7 days in a row."
    * **Mastery**: "Achieve 'Expert' tier in 5 different activities."
    * **Social**: "Finish #1 on a challenge leaderboard."

---

### 📜 The Secret Sauce: Full Transparency

Underpinning the entire system is the **XP Log**. Every single point a user earns is recorded with a reason (`source_type`) and a description. This builds immense trust and engagement, as users can see a detailed history of their achievements, and it makes debugging the system a breeze for you.
The best approach is to merge the two ideas. We'll use the **clean, scalable structure of Idea 2** as the foundation and enhance it with the **robust, auditable logging system of Idea 1**. This gives you the best of both worlds: a system that's easy to understand and manage but also provides a detailed history of every point awarded.

The key improvements in this merged version are:

  * **XPLog for Transparency**: We're including the `XPLog` table from Idea 1. This is crucial for debugging and for showing users *exactly* why they received points, which builds trust.
  * **Lifetime vs. Current XP**: We distinguish between `xp` (current points toward the next level) and `total_points` (a lifetime score for leaderboards), a powerful pattern from Idea 1.
  * **Superior Foreign Keys**: We use Idea 2's approach for `ActivityMastery`, linking directly to `activity_type_id` for better data integrity than using a simple string.
  * **Clear Enums**: We'll use the explicit `MasteryTier` from Idea 2 and the `XPSourceType` from Idea 1 to make the data clear and readable.

### 3\. New Models to Add

Finally, add these new models to the end of your `schema.prisma` file.

```prisma
// --- NEW GAMIFICATION MODELS ---

// Tracks a detailed history of all XP transactions for transparency and debugging.
model XPLog {
  id          String       @id @default(uuid()) @db.Uuid
  profile_id  String       @db.Uuid
  source_type XPSourceType // What action generated the XP? (e.g., ACTIVITY)
  source_id   String?      // The ID of the source (e.g., the specific Activity.id)
  points      Int          // How many points were awarded
  description String?      // A human-readable description (e.g., "Completed Running (5.2 km)")
  created_at  DateTime     @default(now()) @db.Timestamptz(6)

  profile Profile @relation(fields: [profile_id], references: [id], onDelete: Cascade)

  @@map("xp_logs")
}

// Tracks a user's progress and mastery level for a single activity type.
model ActivityMastery {
  id               String      @id @default(uuid()) @db.Uuid
  profile_id       String      @db.Uuid
  activity_type_id String      @db.Uuid
  total_value      Float       @default(0) // Cumulative value (km, reps, minutes, etc.)
  mastery_tier     MasteryTier @default(NOVICE)
  created_at       DateTime    @default(now()) @db.Timestamptz(6)
  updated_at       DateTime    @updatedAt @db.Timestamptz(6)

  profile       Profile      @relation(fields: [profile_id], references: [id], onDelete: Cascade)
  activity_type ActivityType @relation(fields: [activity_type_id], references: [id], onDelete: Cascade)

  @@unique([profile_id, activity_type_id])
  @@map("activity_masteries")
}

// Defines the master list of all possible badges in the system.
model Badge {
  id          String        @id @default(uuid()) @db.Uuid
  name        String        @unique
  description String
  category    String        // e.g., "Feats", "Mastery", "Social"
  icon_url    String?
  xp_bonus    Int           @default(150) // Bonus XP for earning the badge
  created_at  DateTime      @default(now()) @db.Timestamptz(6)
  
  earned_by   EarnedBadge[]

  @@map("badges")
}

// A join table that connects a Profile to a Badge they have earned.
model EarnedBadge {
  id         String   @id @default(uuid()) @db.Uuid
  profile_id String   @db.Uuid
  badge_id   String   @db.Uuid
  earned_at  DateTime @default(now()) @db.Timestamptz(6)

  profile Profile @relation(fields: [profile_id], references: [id], onDelete: Cascade)
  badge   Badge   @relation(fields: [badge_id], references: [id], onDelete: Cascade)

  @@unique([profile_id, badge_id])
  @@map("earned_badges")
}
```

## ⚙️ How It Works: Example Flow

This schema elegantly handles the core gamification loop. Let's trace what happens when a user logs an activity.

1.  **User logs an `Activity`**: Your application backend receives the new activity data (e.g., `activity_type_id` = 'running-uuid', `value` = 5.2).
2.  **Calculate XP**: Your backend logic calculates the XP to award. For example: `50` (base) + `5.2 * 10` (10 XP per km) = `102 XP`.
3.  **Update Profile and Log XP**: You perform a single database transaction to ensure data consistency. This transaction does three things:
      * Increments `xp` and `total_points` on the `Profile` model.
      * Creates a new entry in the `XPLog` table with all the details (`source_type: 'ACTIVITY'`, `source_id: 'activity-id'`, `points: 102`).
      * Updates the user's `ActivityMastery` for "Running" by adding `5.2` to its `total_value`.
4.  **Check for Level Up**: After the transaction, your code checks if the user's new `xp` total exceeds the threshold for their next level. If it does, you update their `level` and reset their `xp` for the new level's progression.
5.  **Check for Mastery Tier Up**: You also check if the new `total_value` in `ActivityMastery` crosses a threshold for a new tier (e.g., from "Novice" to "Adept"). If so, you update the `mastery_tier` field.
6.  **Check for Badges**: Finally, your logic checks if this action (or the new mastery tier/level) unlocks any new badges. If the "Run 100km" badge is unlocked, you create a new `EarnedBadge` entry.

This combined schema provides a powerful, scalable, and transparent foundation for building an engaging gamification system.
